# nue-host — Security

## Модель угроз

`nue-host` — локальный dev/отладочный сервер. Он выполняет две функции:
раздаёт статический Next.js-экспорт и проксирует `/v1/*` на удалённый ai2
host. Компрометация означает чтение локальных файлов или использование хоста
как прокси-шлюза. Порт слушает только `127.0.0.1`, поэтому прямой внешний
доступ невозможен; атака возможна только с локальной машины (злая веб-
страница в браузере через fetch, либо локальный процесс).

В демо-режиме (`--demo` / `NX_NUE_DEMO=1`) сервер **не** запускает
`nx connect` и не делает сетевых вызовов: поверхность атаки сводится к
локальной статике и синтетическим данным. Прокси-ветка `/v1/*` в демо
не активна.

## Смягчения (реализованы в коде)

| Опасность | Правило | Где |
|---|---|---|
| Обход корня абсолютным путём (`C:/…`, `D:/…`, `\\server\share`, `/…`) | Сегменты с `:` отбрасываются; после склейки проверяются `is_absolute()` и `components()` на `Component::Prefix/RootDir`; `candidate.starts_with(root)` — страховка | `resolve_path` в `src/lib.rs` |
| Обход корня через `..` (в т.ч. percent-encoded `%2e`, `%2f`, `%252e`) | Сегмент `..` → 404 | `resolve_path` |
| NTFS Alternate Data Streams (`file.txt:stream`) | Любой сегмент с `:` → 404 | `resolve_path` |
| DNS-rebinding (чужой `Host`) | Принимаются только `localhost`, `127.0.0.1`, `[::1]` (порт игнорируется); иначе 421 Misdirected Request | `host_allowed` в `src/lib.rs` |
| Несогласованные методы на статике | Только `GET`/`HEAD`; иначе 405 | `serve_static` |
| Маскировка 404 (все пути → index.html) | Резолвинг `{path}` → `{path}.html` → `{path}/index.html` → 404; слепого SPA-fallback нет | `serve_static` |
| `Transfer-Encoding: chunked` | Не поддерживается → 411 Length Required (битое тело не уходит в апстрим) | `handle` |
| Прокси-эскап (`/v1/../…`, двойной `/v1/v1/…`) | `strip_prefix("/v1/")` ровно один раз; сегменты `..` в остатке → 404 | `proxy` |
| Нераспознанный метод в прокси | 405 (вместо 404) | `proxy` |
| Query-строка в `/api/*` и статике (G-6-1) | Путь режется по `?` (`path.split("?")[0]`) во всех ветках; query в логике не разбирается | `handle_with` / `api_farm_with` |
| Скрытые пути в статике | Сегменты, начинающиеся с `.`, и `node_modules` → 404 (dotfiles, `.git`, `.env`, `.well-known`) | `resolve_path` |
| Не-GET на `/api/*` | Только `GET`; POST/PUT/DELETE/PATCH → 405 | `api_farm_with` |
| Утечка внутренностей фермы (cwd/argv/env/pid) | Каждый ответ — whitelist-проекция; `cwd`/`argv`/`env`/`pid` не попадают ни в один JSON | `farm.rs` |
| Утечка home-путей | Маска `C:\Users\***`, `/home/***`, `/Users/***` в любом тексте ответа | `_clean_text` в `src/farm.rs` |
| Секреты фермы | Отдаются только проекции (deck_agents/roster/core_agents/core_terminals); сырые RPC-ответы наружу не идут | `farm.rs` |
| Смерть фермы в SSE | При потере соединения — `{"error":"farm_lost"}` вместо вечного молчания | `sse_farm_with` |

## Лимиты

- Тело запроса: максимум 16 МиБ (`MAX_BODY`) — превышение → закрытие
  соединения.
- Заголовки: максимум 64 КиБ — превышение → закрытие соединения.
- Read-таймаут соединения: 30 с.
- Соединения: `Connection: close`, поток на соединение (лимита на число
  соединений нет — намеренно, для dev-хоста).

## Что намеренно НЕ делается

- Прокси не аутентифицирует: `Bearer`/`X-API-Key` несёт клиент, сервер не
  хранит и не логирует секреты.
- Ответы несут `Access-Control-Allow-Origin: *` (необходимо для открытия
  бандла с другого origin); это допустимо, поскольку сервер слушает только
  `127.0.0.1` и не отдаёт файлы за пределами root.
- `/api/*` не отдаёт сырые ответы RPC-ядра — только whitelist-проекции
  (`farm.rs`). Это сознательное ограничение: клиент не видит внутренние
  поля (cwd/argv/env/pid, секреты, полные машины), даже если они есть в
  RPC-ответе.

## Модель доверия

Данные фермы (через `/api/*`) считаются **недоверенными** до санитайзера:
любой текст (name/title/msg/labels) проходит `_clean_text` (лимит 160,
контрольные символы, маска home) перед тем как попасть в ответ. Поле
`state`/`agent_state` приводится к enum-проекции `_core_state`; произвольные
значения не проходят (→ "idle"). Клиент на `127.0.0.1` сам по себе не
является привилегированным: он получает те же проекции, что и любой
локальный процесс.

## Отчёт об уязвимостях

Проблемы безопасности принимаются через корневой `SECURITY.md` workspace'а
(см. `README.md` крейта для ссылок); эксплойт-детали в публичных issue не
публикуются. При использовании крата как отдельного корня верхнего уровня —
через `SECURITY.md` того репозитория, в который входит `nue-host`.
